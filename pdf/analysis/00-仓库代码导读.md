## 1. 运行时拓扑

本地 Compose（`infra/docker-compose.yml`）把系统拆成「有进程的服务」和「被它们调用的库」：

```
浏览器  :8010  apps/copilot_console
              │  /api/* 反代到 Product API
              ▼
         :8002  services/copilot_api     身份 / 会话 / 编排 / 审计
              ├─ :8000  services/rag_api      检索 + 生成 + Graph 路由
              └─ :8001  services/tool_api     工单工具 / KPI / Skill / HITL
              │
              ▼
         :15432 postgres+pgvector        结构化事实、chunk、向量、发布指针
         :9000  minio                    raw 对象（文档/音视频）
         :3000  dagster                  资产图（多数是 CLI 的 thin wrapper）
         :6006  phoenix + otel_collector 请求级 trace
```

三个 FastAPI 进程的职责不要混：

| 进程 | 端口 | 对外承诺 | 不该做的事 |
|---|---|---|---|
| `copilot_api` | 8002 | 登录、租户、会话、把一次问答/动作编排完 | 自己做向量检索或直接写工单业务逻辑 |
| `rag_api` | 8000 | 带 citation / evidence / release 的回答 | 改工单、走 HITL |
| `tool_api` | 8001 | Schema / 幂等 / 权限 / 审计约束下的动作 | 生成自然语言答案 |

浏览器**从不**直连 Postgres、RAG 内部表或写工具。产品路径必须经过 Product API 的身份和租户校验。

课堂路径可以绕过控制台：直接 `curl :8000/api/v1/query` 或跑 `python -m pipelines...`。Capstone 产品路径走 `:8010` → `:8002` → `:8000/:8001`。

## 2. 两条主链

整仓只有两条必须能默画的链。其余目录都是挂在这两条链上的零件。

### 2.1 数据链：资格 → 落盘 → 可服务

```
contracts/data/*.json                 合格标准
data/seed_manifests/*.json            这一批发什么
pipelines/ingestion/seed_loader.py    门禁（accept/warn/quarantine/reject）
pipelines/ingestion/ticket_ingest.py  工单 Bronze+Silver（幂等）
pipelines/ingestion/doc_ingest.py     文档元数据 + MinIO
pipelines/lakehouse/materialize.py    Postgres → Iceberg snapshot
analytics/models/**                   dbt staging → marts → agent_tool_input_view
pipelines/parse_normalize/run_parse.py  结构保真解析 + chunk + evidence + quality gate
pipelines/indexing/embedder.py        knowledge_section → pgvector
pipelines/graph/build.py              图派生资产
release/generator.py                  把 data/index/prompt/graph/skill/eval 锁进一份 manifest
```

Dagster 入口是 `pipelines/definitions.py`。多数 `@asset` **不复制业务逻辑**，只调用上面这些 CLI 模块。读代码时优先 CLI 模块，资产文件当依赖图看。

Capstone 把整条数据链收成一个编排器：`scripts/capstone/bootstrap.py`，阶段是 `ingest → knowledge → analytics → graph → release`。Dagster 的 `pipelines/capstone/assets.py` 再包一层同样的 `run()`。

### 2.2 请求链：问答与动作

**问答（产品）：**

```
apps/copilot_console/app.js
  POST /api/v1/conversations/{id}/messages
    services/copilot_api/app/main.py  ask_copilot()
      写 support_message(role=user)
      POST rag_api /rag/answer
        services/rag_api/app/routers/rag.py
          query_rewrite → classify_query
          hybrid: retrieval.py (vector + FTS + RRF + rerank)
          或 graph: services/graph/retrieval.py
          context_pruning → generator.generate_grounded_answer
      写 support_message(role=assistant) 带 citations / 五类 release_id / trace_id
```

**问答（课堂，Week08 起）：** `POST :8000/api/v1/query` → `services/rag_api/app/routers/query.py`。链路更短，没有 Product API 的会话和租户表。两套端点共用 `retrieval.py` / `generator.py`。

**动作（产品）：**

```
POST /api/v1/cases/{ticket_id}/actions
  copilot_api.execute_case_action()
    校验角色、金融动作必须带本案 evidence_ids
    POST tool_api /api/v1/tools/ticket_update
      services/tool_api/app/routers/tickets.py
        JSON Schema + 幂等键 + HITLPolicy
        高风险 → hitl_approval_request，批准前不执行
        执行后写 audit_log / agent_action_lineage
```

Skill Registry（Week09）在 Tool API 的 `GET /api/v1/skills`，**只发现、不执行**。真正改状态的永远是 Tool Contract。

## 3. 贯穿全仓的 ID

读任何一周代码，先盯这些字段。它们比类名重要。

| ID | 谁写 | 谁读 | 断了会怎样 |
|---|---|---|---|
| `source_id` / `source_fingerprint` | ingest | lakehouse / parse | 同一文件会被当成新资产 |
| `ingest_batch_id` / `checkpoint` | Week03 ingest_state | replay / backfill | 失败后不知道从哪续 |
| `snapshot_id` | Iceberg materialize | time travel / release | 评测绑不住「哪一版表」 |
| `evidence_id` + `page_no` / `bbox` / `section_path` | Week07 parse | RAG citation、金融动作校验 | 能召回但不能指回原文 |
| `chunk_id` | parse / index | retrieval | 索引和证据对不上 |
| `index_release_id` / `data_release_id` | indexer | retrieval 过滤 | 搜到旧文档或混代数据 |
| `prompt_release_id` | rag_api settings | 生成 / 发布绑定 | 回答变了无法归因 Prompt |
| `graph_release_id` | graph build | GraphRetriever | 图检索打到未激活版本 |
| `skill_release_id` | Skill digest | Week14 manifest | Skill 内容和发布脱钩 |
| `trace_id` | OTel / 中间件 | Phoenix、审计、血缘 | 一次请求串不成树 |
| `release_id`（总指针） | release registry | 所有服务配置、回滚 | 昨天那套回不去 |
| `idempotency_key` | 调用方 | tool_api | 网络重试会重复扣款/建单 |
| `approval_id` | HITL | 审批决策端点 | 高风险动作没有检查点 |

Product API 写 `support_message` 时会把 `data/index/prompt/graph/release_id` 五个一起落库。这是 Week14「原子绑定」在请求链上的可见形状。

## 5. 三个「看起来像两套实现」的地方

课程为了让 PPT 路径稳定，留了若干 **转包模块**。不知道的话会读错文件。

| 你可能先打开的 | 真正的实现 | 关系 |
|---|---|---|
| `pipelines/retrieve/hybrid.py` | `services/rag_api/app/retrieval.py` | 文件头写明：不要在这里加检索逻辑 |
| `pipelines/query/rewriter.py` | `services/rag_api/app/query_rewrite.py` | 同样是转包 |
| `pipelines/graph/store.py` | `services/graph/store.py` | 构建期 vs 服务期；检索走 services |
| `tools/registry.py` | `services/tool_api/app/tool_contract_registry.py` | 发现描述 vs 运行时校验 |
| `POST /api/v1/query` | `POST /rag/answer` | 课堂短链路 vs 产品契约（含 Graph 路由、五类 release） |
| `pipelines/*/assets.py` | 同目录的 `run_*.py` / `*.py` CLI | Dagster 观察同一份 CLI，不是第二套 parser/indexer |
| 讲义里的 `lakectl` / lakeFS 集群 | `data/lakefs/config.yaml` + `release/` | Student Core 只有策略和指针，没有 lakeFS 服务 |

判断口令：**一份能力只应有一个 source of truth。** 若两个文件都像在做事，先读 docstring 里的 “thin wrapper / do not add logic here”。

## 8. 一次请求的代码级走位

以坐席在控制台提问为例（产品路径，不是课堂 curl）：

1. `app.js` 带 JWT 调 Product API。
2. `ask_copilot` 先落用户消息，再组 `RagAnswerRequest`（tenant、product_line、role、retrieval_mode）。
3. 内部调用带 `X-Service-Token` + `X-Tenant-ID` + `X-Request-ID`，防止浏览器直打 RAG。
4. `rag_answer` 开根 span `rag.query`（名字以实际代码为准），子 span 覆盖 rewrite / retrieve / generate。
5. `classify_query` 若判 hybrid：`hybrid_retrieve` 同时打 pgvector 与 FTS，RRF 融合后再可选 rerank。
6. 若判 graph_*：`GraphRetriever` 读当前 **active** `graph_release_id`，失败则按代码里的 fallback 回 hybrid（具体原因码看 `graph_fallback_reason`）。
7. `generate_grounded_answer` 受输出 Schema 约束；无密钥时走 deterministic fallback，响应里仍有 `generation_mode`。
8. Product API 把 answer、citations、evidence_ids、五类 release、trace、模型字段写入 `support_message`。
9. 反馈走 `POST /api/v1/messages/{id}/feedback` → `copilot_feedback`，供 Week11 闭环，不在线改模型。

写动作把第 5–7 步换成 Tool API：Schema 校验 → 幂等表 → HITL 条件 → 事务内执行或挂起审批。金融类还要求 evidence 必须已经出现在**本案**会话里（`_validate_action_evidence`）。

## 9. 排障时打开哪一层

| 现象 | 先看 | 不要先看 |
|---|---|---|
| Compose 起不来 / health 红 | `infra/docker-compose.yml`、`001_init.sql`、`.env.local` | Prompt、向量维度 |
| seed dry-run 被拒 | `seed_loader.py` + 对应 contract + manifest | parse / RAG |
| 工单重复或补数乱跑 | `ticket_ingest.py` 幂等键、`ingest_state.py` | Iceberg |
| 「表在但回不到昨天」 | `inspect_metadata.py` / snapshot | pgvector |
| KPI 和坐席说法不一致 | `metric_registry_v1.yml` + mart SQL | LLM |
| 能搜到但不能高亮原文 | `evidence_anchor.py`、chunk metadata | rerank 阈值 |
| 订单号 / 错误码搜不准 | `retrieval.py` 的 FTS 路 | 换 embedding 模型 |
| 工具连打三次生效三次 | `tickets.py` 幂等、`idempotency_key` | HITL UI |
| Phoenix 里看不到树 | `observability/runtime`、服务是否 `instrument_fastapi_app` | 评测集 |
| 全局归纳题答成 FAQ | `classifier.py` 是否走到 graph_global | BM25 参数 |
| 回滚了代码答案仍错 | `release/registry.py` 当前指针、`index_release_id` | git log |

## 11. 明确不要做的读法

- **不要从 `services/` 第一个文件读到最后一个。** 三个 API 进程加上 graph 库，会把 W01 骨架和 W15 产品搅在一起。
- **不要把 `pipelines/retrieve` 当成检索主实现。** 主实现在 `services/rag_api/app/retrieval.py`。
- **不要在 Dagster UI 里找 parser 源码。** UI 只是物化入口。
- **不要假设讲义路径存在。** 先看该周笔记第 7 节。
- **不要把 Iceberg、pgvector、RAG 响应当成同一份「当前知识」。** 湖是账本，索引是服务副本，响应是某次 release 的投影。
- **不要为了「完整」去读讲义 PDF。** 学习用 `pdf/analysis`；原幻灯片在 `pdf/doc`。

## 12. 最短代码闭环（对应讲义地图第 9 节）

1. Compose + `test_json_schemas.py`（W01 骨架真的在跑）
2. `seed_loader` dry-run（W02 门禁）
3. `retrieval.py` + 一次 `/api/v1/query` 或产品 `/rag/answer`（W08 证据字段）
4. `tickets.py` + HITL（W10 动作边界）
5. `release/registry.py` + `rollout/rollback.py`（W14 指针）
6. 有余力再跑 `scripts/capstone/bootstrap.py` + `verify_e2e.py`（W15 串珠）

读代码的完成标准不是「目录都点开过」，而是能不看笔记画出：一次问答经过哪些进程、一次 ingest 经过哪些模块、一个 `release_id` 绑了哪些对象。
