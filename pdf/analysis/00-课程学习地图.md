## 0. 怎么用这套笔记

每份周笔记都按同一结构写：主干 → 逐课时干货 → 概念对照代码 → 讲义与仓库不一致处 → 动手清单 → 易错点 → 自测题。

建议节奏（一周大约 3–5 小时，不含把视频完整刷完）：

1. 读该周笔记第 0 节和第 11 节，建立位置感（10 分钟）
2. 读 1–5 节的框架和对照表，遇到自测题先试着答（40–70 分钟）
3. 打开第 6 节的仓库路径，只看这一周对应的文件，不要顺藤摸整仓（40–90 分钟）
4. 按第 8 节跑 Docker 命令，用验收问题而不是"跑过了"当完成标准
5. 视频只回看笔记里卡住的那一幕，不要按倍速从头到尾陪跑

原讲义的水分主要在：开场故事、行业信号页、重复的 Week 地图、"学完你能做到"。笔记已经删掉这些。精炼判断句（如"schema 看长相，contract 看资格"）会保留原文。

## 1. 要不要先分析代码？

**不必先把整个仓库通读一遍。**

正确顺序是：

```
讲义立主干（这套笔记）
    → 只打开本周映射表里的文件，核对讲义有没有说错路径
    → 跑本周动手清单
    → 下一周再重复
```

原因很具体：

- 这是一门**按周叠加的单仓课**，W15 的代码里已经有 W01–W14 的全部能力。一上来通读，你会把后面才教的 HITL、GraphRAG、lakeFS 策略和第一周的骨架搅在一起。
- 讲义路径经常过时（YAML manifest、不存在的 csv 路径）。笔记第 7 节就是为这个准备的。不对照代码，你会在仓库里找一份讲义里的幽灵文件。
- 代码是处方，讲义是诊断。先诊断再看处方，才知道一段 `idempotency_key` 是在补哪一层失守。

什么时候应该看代码：读完该周第 6 节映射表之后。什么时候不要看代码：还没搞清本周在整条链上补哪一层之前。

代码总图用 [00-仓库代码导读.md](00-仓库代码导读.md)：两条主链、贯穿 ID、按周 4–8 个文件的切片。仓库里另有一份更厚的导读 `docs/guides/omnisupport-copilot-student-code-reading-reference.docx`，那是整仓放大镜，不是每周入门。

## 2. 这门课到底在建什么

虚构企业 **Northstar Systems**，三条产品线（Workspace / Edge Gateway / Studio），做一个准生产级客服 Copilot：文档问答带证据、工单查询/创建/更新、KPI 查询、HITL、审计、评测、版本回滚。

产品入口（全部能力串起来之后）：`http://localhost:8010`

一句话定位：不是聊天框套 LLM，是坐席的**证据与动作控制面**。

贯穿 15 周的实施原则：

| 原则 | 含义 |
|---|---|
| Data-first | 先数据层、边界、契约，再生成层 |
| Workflow-first | 先稳定工作流，再复杂 Agent |
| Evidence-first | 回答必须带 evidence / citation |
| Release-aware | 预埋 `release_id` / `trace_id` / `eval_run_id` |
| Dual-scale | 本地 Student Core Pack 可跑，再谈规模 |

## 3. 三张必须对齐的图

讲义用了三套"层"，编号不完全相同。学习时认职责，别死磕数字。

### 3.1 五层诊断（事故复盘用）

Week01 用来拆事故，后面每周补一层：

| 层 | 周次 | 核心问题 |
|---|---|---|
| 数据与输入 | W02–04 | 数据从哪来，怎么稳定进系统 |
| 检索与证据 | W07–08，W13 补位 | 搜得到、答得稳、引得回 |
| 工具与动作 | W09–10 | 从会答到能办，边界在哪 |
| 评测与观测 | W11–12 | 效果怎么量、问题怎么找 |
| 治理与发布 | W14–15 | 怎么发、怎么回、怎么稳定跑 |

W05–06 是横切：口径资产化、编排资产化，不是第六条平行故事。

### 3.2 交付链顺序（比名词重要）

```
业务目标
  → 数据盘点 → 数据契约 → 采集入湖
  → 湖仓 / 语义 / 编排 / 解析
  → 索引检索 → 生成与工具
  → 评测观测 → 版本治理 → 上线回滚
```

顺序乱了就会边做边返工。这就是为什么课不从 RAG 第一周开始。

### 3.3 仓库七层（实现用）

```
L7 Agent / Tool          Skill / 工具契约 / HITL / 审计
L6 Serving / Retrieval   pgvector + FTS + RRF + RAG API
L5 Lakehouse             Iceberg Bronze / Silver / Gold
L4 Parse / Normalize     文档 / ASR / 视频 / PII / chunk / evidence
L3 Landing / Raw         MinIO
L2 Contracts             数据 / 工具 / 发布契约
L1 Source                工单、文档、音视频、配置
贯穿 Observability         OTel + Phoenix + OpenLineage + evals + release
```

## 5. 四个阶段，对应你在项目里的角色切换

```
Phase 0   W01           开工：骨架、契约、边界、蓝图
Phase 1   W02–03        输入能进门：盘点、契约、采集、状态
Phase 2   W04–08        事实能站住：湖仓、口径、编排、解析、RAG
Phase 3   W09–15        动作能负责：Skill、HITL、评测、观测、图、发布、成本
```

一个实用的自我检查：

- 还在调 Prompt 解决"答案忽高忽低" → 先回到 W02 输入层，不要跳到 W08
- citation 开始失效 → W07 证据锚点，不是 W08 top-k
- 工具把退款扣了三次 → W10 幂等，不是换模型
- "过去半年 P0 共性是什么" 答非所问 → 这是 W13 主场，W08 向量召回本来就不是为它设计的
- 昨天对今天错、回不去 → W04 状态账本 + W14 release 绑定，不是重跑一次 ingest

## 6. 仓库怎么按周切开看

不要按"目录树从左到右"读。按主链读：

```
contracts/          资格：数据 / 工具 / 发布 / 评测 / Skill
data/               原料：manifest、种子、合成器
pipelines/          生产：ingest → lakehouse → parse → index → graph → capstone
analytics/          口径：dbt + metric registry
services/           服务：rag_api / tool_api / copilot_api / graph
apps/               产品：copilot_console
skills/             工艺包：给 Agent 的手册，不是业务动作本身
evals/              尺子：golden set、指标、回归门禁
observability/      显微镜：OTel / Phoenix / SLO / bad case
release/ + rollout/ 发布与回滚
tests/contract      先于实现的边界检查
docs/blueprints     该周设计意图（比代码更早写清"不做什么"）
runbooks/           人该怎么操作
```

本地默认端口：RAG `8000`、Tool `8001`、Product API `8002`、控制台 `8010`、Dagster `3000`、MinIO `9001`、Phoenix `6006`、Postgres `15432`。

## 7. 一条贯穿全课的口令

排障时先问层，再问动作：

```
输入契约 / manifest
  → ingest batch / checkpoint
  → Iceberg snapshot
  → chunk / evidence
  → index version
  → prompt / skill version
  → tool / HITL
  → eval / trace
  → release_id
  → 回滚目标（数据状态，不只是代码）
```

看到系统"变歪"，优先用这串口令定位。大部分"AI 不行了"其实是某一环的版本没绑上。

## 8. 学习上最容易浪费时间的五件事

1. **把 15 周视频当音频书刷完。** 用笔记 + 自测题定位，再定点回看。
2. **第一周就想把 Copilot 答准。** Week01 的验收是五个工程承诺，不是 NDCG。
3. **讲义写了路径就去仓库里搜。** 先看该周笔记第 7 节。
4. **为了"完整"通读 services/ 下所有文件。** 按第 6 节映射表看切片。
5. **把 GraphRAG / Agent 当成 RAG 的升级版。** 它们是不同题型的补位，不是更强检索。

## 9. 如果你只有很短的时间

最低闭环（仍然按顺序，不可跳）：

1. Week01 笔记 + 把 Compose 和契约测试跑绿
2. Week02 笔记 + seed_loader dry-run（整门课的输入门禁）
3. Week08 笔记 + RAG 冒烟（看到 citations / release_id / trace_id）
4. Week10 笔记（理解"办错一件事"和"答错一句话"不是同一类风险）
5. Week14 笔记（理解什么叫一个可回滚的 release）

有余力再按 W03–07、W09、W11–13、W15 把链补全。Capstone 不是另做一个项目，是把上述能力在 `localhost:8010` 上串成产品。
