# 学习文档编写规格（供各周分析统一遵循）

## 背景

学员在学习极客时间《AI 数据工程实战营》。课程共 15 周，配套代码仓库是
`omnisupport-copilot`（本仓库）。学员认为原讲义啰嗦、重复多，需要一份
"去水但不丢干货"的学习文档。

## 输入

- 讲义原文：`pdf/doc/*.pdf`
  - 需要纯文本对照时，运行 `python pdf/tools/extract_text.py`
  - 输出在 `pdf/_extracted/weekNN.md`（gitignore，不提交）
  - 每页以 `## [pNN]` 分隔
  - 每页开头重复出现的导航条和页码是幻灯片模板噪音，直接忽略
  - PPT 文本按视觉位置抽取，偶有顺序错乱，需结合上下文理解
  - Week01 等图片型 PPT 文本层可能为空，只能对着 PDF 读
- 代码仓库：仓库根目录，结构见 `README.md`

## 输出

写入 `pdf/analysis/weekNN-<简短中文主题>.md`，一个文件。

## 样板

`pdf/analysis/week02-输入确定性与数据契约.md` 是已经定稿的样板。
**动笔前必须先读一遍**，严格对齐它的结构、语气和信息密度。

## 结构要求

```
# Week NN · <主题>

> 一句话：<本周到底解决什么问题，用一句话说清>
> 讲义：pdf/doc/<原文件名>.pdf（NN 页 / N 课时）

## 0. 本周主干
   用一个简单的流程/链路图展示 5 节课如何串成一条线。
   如果讲义里有好的记忆法或口诀，单独提出来。

## 1..5. 逐课时提炼
   每个 lesson 一节，标题写成 `## N. LNN · <小标题>`。
   只保留：核心论点、分类框架、判断标准、对照表、具体字段/参数。
   删掉：开场铺垫、"这节课解决什么"、"学完你能做到"、
        重复出现的 Week 地图、纯励志话术。
   讲义里的"行业信号"页（引用 Anthropic / OpenAI / NIST / OpenLineage 等）
   通常是凑数内容，最多压缩成一两句话，或直接删掉。

## 6. 概念 → 代码映射
   表格三列：讲义概念 | 仓库位置 | 重点看什么。
   **所有路径必须实际核对存在**，用 Glob/Read 验证过再写。
   之后可加一个小节，讲代码里值得单独看、但讲义没展开的细节
   （比如默认参数、硬编码策略、schema 约束）。

## 7. 讲义与仓库对不上的地方
   讲义写了但仓库里没有的路径/命令，明确列出来提醒别浪费时间找。
   如果没有，写"暂未发现"，保留这一节。

## 8. 动手清单
   本周该跑的命令（从讲义和 README 里找，优先用 Docker devbox 路径）。
   关键是给出**验收标准**：不是"跑过了"，而是能回答哪几个问题。
   可以加"加分练习"。

## 9. 易错点与边界
   分两部分：
   - 概念层面：最容易混淆的 A ≠ B
   - 范围边界：本周刻意不做什么、留给了哪一周

## 10. 自测题
   8-12 题，覆盖本周全部课时，只给问题不给答案。
   要问"为什么""区别是什么""什么情况下选 A 不选 B"，
   不要问能背诵的定义。

## 11. 一句话收口
   本周在整门课里的位置和价值。
```

## 写作要求

1. **中文为主**，专有名词、字段名、路径、命令保留英文原文。
2. **表格优先**。讲义里大量对照关系（A vs B、四类资产、五种模式、
   三级兼容性）用表格表达最省读者时间。
3. **不要复述讲义原句**，要重新组织。但讲义里精炼的判断句
   （如"schema 看长相，contract 看资格"）值得原样保留。
4. **代码块**用 markdown fence，标注语言。引用仓库现有代码时
   贴关键片段即可，不要大段复制。
5. **密度**：一周文档 300-500 行。比讲义短得多，但信息不丢。
   宁可多花时间压缩，也不要写成流水账。
6. 不要用 emoji。不要写"总之""综上所述"这类过渡废话。

## 交付前自检

- [ ] 概念映射表里每条路径都实际验证过存在
- [ ] 没有遗漏任何一个 lesson
- [ ] 结构与 week02 样板一致
- [ ] 自测题能真正检验理解，而不是背诵
